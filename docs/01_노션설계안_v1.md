# 노션 설계안 v1 — 필요웍스 운영 시스템

- 작성일: 2026-09-26
- 상태: **제안 (대표 검토 대기).** 승인 후 노션에 구축한다.
- 전제: `INTENT.md`의 사업 구조와 원칙을 따른다.

## 0. 지난 설계가 실패한 이유 (다시 하지 않을 것)

기존 `HOME / Work`와 `레흐 레카 대시보드`를 보면:

| 있었던 것 | 문제 |
|---|---|
| 강의 DB 하나에 뷰 7개 | 어느 뷰를 봐야 하는지 매번 고민하게 된다 |
| 기관 DB ← 강의 수·최근 강의일 롤업 | 372건 중 연결된 게 없어서 숫자가 0. 채우려면 372번 클릭 |
| 할 일 체크 비율 → 강의 진행률 수식 | "진척 대상" 체크박스를 또 관리해야 한다. 관리를 위한 관리 |
| 강의 DB가 원본의 "복제본" | 원본이 두 개가 됐다 |
| 자료실 ↔ 강의 양방향 관계 | 어느 쪽에서 연결해야 하는지 불명확 |

**새 설계의 규칙 4개**
1. **롤업과 수식은 쓰지 않는다.** 숫자가 필요하면 뷰의 "개수 세기"로 충분하다.
2. **관계형은 "클릭해서 들어갈 일이 있을 때만", 한 방향으로만.** 연결 안 해도 시스템이 망가지지 않아야 한다.
3. **DB 하나에 속성은 6개 이하.** 채울 칸이 많으면 빈칸이 쌓이고, 빈칸이 쌓이면 그 DB를 안 보게 된다.
4. **DB는 6개.** 그 이상 필요하면 새 DB가 아니라 기존 DB의 "유형" 선택지를 늘린다.

## 1. 하나의 흐름 — 모든 것이 이 순서로 흐른다

```
      ① 일이 들어온다            ② 실행한다              ③ 기록한다
   프로젝트 (강의·제작·상품)  →   업무함 (타스크)   →   히스토리 (강의기록·결정·배움)
                                                              │
      ⑥ 판다 · 공개한다          ⑤ 상품이 된다             ④ 자산이 된다
   프로젝트 (유형=상품·콘텐츠) ←  자산 (공개범위=유료)  ←   자산 (교안·프롬프트·템플릿)
                                                              │
                                                       SOP (반복되면 절차로 굳힌다)
```

말로 풀면:
- **강의 의뢰가 오면** 프로젝트에 한 줄 만든다 (유형=강의).
- **준비할 일**은 업무함에 타스크로 쪼갠다 (담당·마감·완료 기준).
- **강의를 하고 나면** 히스토리에 강의 기록을 남긴다 (이미 있는 「강의 기록」 프롬프트로 AI가 정리).
- 강의에서 만든 **교안·프롬프트·실습 자료**는 자산에 넣는다. 처음엔 "내부".
- 같은 자료를 두세 번 쓰게 되면 → **SOP**로 굳힌다.
- 자산 중 팔 만한 것은 **공개범위를 "무료" 또는 "유료"로 바꾸면** 그게 상품이 된다.
- 상품을 만들고 파는 일 자체가 다시 **프로젝트**(유형=상품 / 콘텐츠)가 된다.

**핵심: "강의 기록 → 자산 → 상품"이 한 워크스페이스 안에서 속성 값만 바꾸며 흐른다.** DB를 옮겨 다니지 않는다.

## 2. DB 6개

### 2-1. 📁 프로젝트 — "덩어리 일" 전부

강의 한 건, 제작 의뢰 한 건, 상품 하나, 유튜브 시리즈 하나가 모두 프로젝트다. **기존 강의 DB 372건은 이 DB로 이동**한다(유형=강의).

| 속성 | 유형 | 선택지 / 설명 |
|---|---|---|
| 이름 | 제목 | "2026-10-15 한국폴리텍 서울강서 · AI 활용 문서작성" 처럼 날짜·기관·주제 |
| 유형 | 선택 | 강의 / 제작의뢰 / 상품 / 콘텐츠 / 코칭 / 내부 |
| 파트 | 선택 | AI교육 / 시스템구축 / 코칭 / 공통 |
| 상태 | 상태 | 예정 → 진행 → 완료 / 보류 |
| 일자 | 날짜 | 강의일, 납품일, 출시일. 시작일 없이 **마감일 하나** |
| 고객 | 텍스트 | 기관명·고객명. **DB로 만들지 않는다** (아래 2-7 참고) |

페이지 본문 템플릿: `개요(목적·대상·범위) / 완료 기준 / 진행 메모 / 결과 · 회고 링크`

### 2-2. ✅ 업무함 — 오늘·이번 주 실행 단위

| 속성 | 유형 | 설명 |
|---|---|---|
| 할 일 | 제목 | 동사로 끝나게: "강의계획서 보내기" |
| 담당 | 선택 | 나 / 에이전트. (사람이 늘면 "사람" 속성으로 교체) |
| 마감 | 날짜 | |
| 상태 | 상태 | 요청 → 진행 → 회신완료 → 완료 / 보류 |
| 프로젝트 | 관계형 (→프로젝트, 단방향) | 어느 덩어리의 일인지. 없어도 된다 |
| 완료 기준 | 텍스트 | 한 줄. "PDF가 담당자 메일로 발송된 상태" |

뷰는 2개만: **오늘·이번주**(마감 순, 완료 숨김) / **전체**.
에이전트에게 시킬 일도 여기에 넣는다. 에이전트는 "회신완료"까지, 완료는 대표가 누른다.

### 2-3. 📙 히스토리 — 암묵지를 명시지로

| 속성 | 유형 | 선택지 / 설명 |
|---|---|---|
| 제목 | 제목 | |
| 유형 | 선택 | **강의기록** / 결정 / 배움 / 실패 |
| 일자 | 날짜 | |
| 파트 | 선택 | AI교육 / 시스템구축 / 코칭 / 공통 |
| 프로젝트 | 관계형 (→프로젝트, 단방향) | 강의기록이면 그 강의. 없어도 된다 |

본문 템플릿은 유형별로 다르다:
- **강의기록**: 기존 「강의 기록」 프롬프트의 5단락 그대로 (진행 요약 / 참여자 반응·질문 / 개선 포인트 / 액션 아이템 / 강사 인사이트). 녹음 전사를 넣으면 AI가 채운다.
- **결정**: `이유 → 시점 → 결정 → 그래서 이렇게 세팅` 2~3줄 + 기각한 안.
- **배움 / 실패**: `상황 → 해본 것 → 결과 → 다음엔`.

**이 DB가 "이력 없음" 문제의 답이다.** 강의기록이 50건 쌓이면 "50회 현장에서 모은 질문 N건"이 된다.

### 2-4. 📦 자산 — 재사용하는 모든 것

교안, 프롬프트, 노션 템플릿, 카드뉴스 양식, 홈페이지 코드, 유튜브 스크립트, 촬영 영상.

| 속성 | 유형 | 선택지 / 설명 |
|---|---|---|
| 이름 | 제목 | |
| 유형 | 선택 | 교안 / 프롬프트 / 템플릿 / 코드 / 스크립트 / 영상 / 이미지 |
| 공개범위 | 선택 | **내부 → 무료 → 유료** (이 값이 바뀌는 순간 상품이 된다) |
| 파트 | 선택 | |
| 위치 | URL | 실제 파일이 있는 곳 (드라이브, GitHub, 유튜브 링크). 노션 안에 파일을 쌓지 않는다 |
| 프로젝트 | 관계형 (→프로젝트, 단방향) | 어느 강의·상품에서 나왔나. 없어도 된다 |

### 2-5. 📗 SOP — 반복 절차

| 속성 | 유형 | 선택지 / 설명 |
|---|---|---|
| 이름 | 제목 | "강의 의뢰 접수 → 견적 → 계획서 발송" |
| 유형 | 선택 | 업무절차 / 매뉴얼 / 정책·지침 / 스킬(AI용) |
| 파트 | 선택 | |
| 담당 | 선택 | 나 / 에이전트 / 함께 |
| 상태 | 선택 | 초안 / 사용중 / 폐기 |
| 최종검증 | 날짜 | 마지막으로 "이대로 되는지" 확인한 날 |

본문 템플릿: `① 목적·배경 / ② 참조할 원본(어느 DB, 어느 페이지) / ③ 절차 (번호 + 캡처) / ④ 완료 기준 / ⑤ 80점 품질 기준 / ⑥ 외부 검수 필요 여부 / ⑦ 변경 이력`

### 2-6. 📘 온보딩 — DB가 아니라 페이지 묶음

DB로 만들 이유가 없다. 페이지 5장:
1. **필요웍스는 무슨 업을 하나** (INTENT.md 1~3절)
2. **이름 표기 규칙**
3. **팀 — 대표와 에이전트들의 역할표** (아래 4절 브랜딩과 연결)
4. **자료 지도 — 무엇은 어디에** (SSOT 표: 결정은 히스토리, 절차는 SOP, 파일은 자산의 URL…)
5. **첫 주 안내** — 사람용 / 에이전트용 두 탭

### 2-7. 고객(기관) DB를 안 만드는 이유

지난번엔 "기관 마스터 + 롤업"을 만들었다가 372건이 연결되지 않아 죽은 DB가 됐다. 지금은 프로젝트의 **텍스트 속성**으로 충분하다. 같은 기관이 3번 이상 반복되고 기관별 이력을 자주 찾게 되는 시점에 DB로 승격한다. 그때는 프로젝트→고객 단방향 관계 하나만 추가한다.

## 4. 브랜딩 방향

### 4-1. 포지션

- 지금: "AI 활용법 강사 ○○○" — 개인. 규모가 작아 보이고 시스템 판매로 확장이 안 된다.
- 목표: **"시스템과 구조를 파는 회사"**. 대표는 그 회사의 **1호 사용자이자 실험자**.
- 한 줄: **"필요웍스는 AI가 함께 일하는 구조를 만들어 팝니다. 저희 회사가 첫 번째 사례입니다."**

### 4-2. 작아 보이지 않는 방법 — 에이전트를 팀으로 소개한다

1인 기업이 "팀"으로 보이는 가장 정직한 방법은 **AI 에이전트들에게 역할과 이름을 주고 조직도에 올리는 것**이다. 이게 곧 상품 데모다.

| 역할 | 이름(예시) | 하는 일 | 참조하는 SOP |
|---|---|---|---|
| 대표 | 본인 | 방향, 고객 대면, 검수 | — |
| 기획 에이전트 | (미정) | 강의계획서·제안서·커리큘럼 초안 | 강의 의뢰 SOP |
| 제작 에이전트 | (미정) | 교안·상세페이지·카드뉴스·홈페이지 초안 | 제작 SOP |
| 기록 에이전트 | (미정) | 강의 전사 → 강의기록, 결정 → 히스토리 | 기록 SOP |
| 운영 에이전트 | (미정) | 견적·기안·일정·백업 | 운영 SOP |

각 에이전트는 "이름 + 담당 SOP + 스킬 파일"로 정의되고, 그 정의 자체가 **팔 수 있는 상품**이 된다(고객사에 "제작 에이전트" 세트를 옮겨 심는 식).

### 4-3. 브랜드 구조

```
Feelyoworks (회사 · 일 축)
 ├─ Feelyoworks Class   : AI 교육 (기존 강의)
 ├─ Feelyoworks System  : 시스템 구축 · 템플릿 · 에이전트 (신규, 주력으로 키울 것)
 └─ Feelyoworks Lab     : 만드는 과정 공개 (유튜브 · SNS)   ← 브랜딩의 엔진
on:self by Feelyoworks (삶 축) : 코칭
```
이름은 제안이다. 핵심은 **"Lab"처럼 과정을 공개하는 채널을 브랜드의 한 축으로 못 박는 것.**

### 4-4. 목소리

- "제가 대기업에서 배운" ✗ → **"제가 직접 만들어 써 보니"** ✓
- 완성품 자랑 ✗ → **만드는 과정·실패·수정** ✓ (Build in Public)
- 강사 톤 ✗ → **동료 실험자 톤** ✓ ("같이 만들어 봅시다")
- 모든 공개 콘텐츠 끝에: "이 과정은 필요웍스 시스템 안에서 이렇게 기록됐습니다" → 시스템이 곧 광고

### 4-5. "AI 강의 이력"을 최대로 살리는 법

가진 것: 강의 372건, 기관 CRM(대학·공공기관), 「강의 기록」 프롬프트, 교안·실습 자료.

| 자산 | 어떻게 살리나 |
|---|---|
| 강의 372건 | 프로젝트 DB로 옮기고 **기관 유형·주제로 분류** → "대학 N곳, 공공기관 N곳, 소상공인 N회" 숫자가 프로필이 된다 |
| 강의 기록 | 지금부터 매 강의마다 남긴다 → 반복 질문 = **콘텐츠 소재이자 상품 근거** ("현장에서 가장 많이 막힌 것 10가지") |
| 교안·실습 | 자산 DB에 넣고 공개범위 결정 → 기본판 무료(유튜브·노션 템플릿), 심화판 유료(크몽) |
| 기관 CRM | 시스템 구축 상품의 **첫 B2B 고객 후보** (강의했던 기관에 "우리 팀용 시스템"을 제안) |

## 5. 상품 사다리 — 무료에서 에이전트 판매까지

| 단계 | 상품 | 채널 | 가격 | 역할 |
|---|---|---|---|---|
| 0 | 만드는 과정 영상, 기본 템플릿 | 유튜브, 노션 템플릿 갤러리 | 무료 | 유입·신뢰 |
| 1 | 노션 템플릿 심화판, 카드뉴스 자동화 세트 | 크몽, 자체 스토어 | 저가 | 첫 구매, 후기 |
| 2 | 홈페이지·상세페이지 제작 | 크몽 | 중가 | 제작 이력 |
| 3 | 1인 기업 운영 시스템 구축 + 에이전트 세팅 | 직접 영업, 강의 기관 | 고가 | 주력 |
| 4 | on:self 코칭 (삶의 시스템) | 직접 | 고가·구독 | 장기 |

**모든 상품은 같은 흐름에서 나온다**: 만든다(프로젝트) → 과정을 찍는다(자산: 영상) → 기본은 무료로 푼다(자산: 공개범위=무료) → 심화판을 판다(공개범위=유료) → 판매 과정도 SOP가 된다.
